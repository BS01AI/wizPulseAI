## 什么是配置中心

配置中心是WizPulseAI的**运行时配置管理系统**，允许管理员在线修改系统配置，**无需重启服务器**。

### 核心优势

| 优势 | 说明 |
|------|------|
| 🚀 **零停机更新** | 修改后5分钟内生效，无需重新部署 |
| 🎯 **业务人员赋能** | 产品经理可自主调整限额，无需技术团队 |
| 📊 **可视化管理** | Dashboard图形界面，操作简单直观 |
| 🔒 **权限保护** | 只有管理员（admin角色）可修改 |
| ⏱️ **配置历史** | 完整变更记录，支持回溯和审计 |

---

## 如何访问配置管理界面

### 步骤1：登录Dashboard

1. 访问 [https://dashboard.wizpulseai.com](https://dashboard.wizpulseai.com)
2. 使用管理员账号登录（必须是`admin`角色）

### 步骤2：进入配置中心

导航路径：**Dashboard** → **管理员功能** → **配置中心**

或直接访问：[https://dashboard.wizpulseai.com/dashboard/admin/config](https://dashboard.wizpulseai.com/dashboard/admin/config)

### 步骤3：查看当前配置

界面分为4个分类：
- **业务限额配置**（控制用户使用量）
- **功能开关**（启用/禁用功能）
- **站点配置**（网站基础信息）
- **第三方服务配置**（外部服务开关）

## 配置项完整说明

### 1️⃣ 业务限额配置 (limits)

控制用户的使用限额，防止滥用。

| 配置键 | 默认值 | 说明 | 修改影响 |
|--------|--------|------|----------|
| `limits.freeUserDailyLimit` | 10 | 免费用户每日使用限额 | 调整免费用户可用次数 |
| `limits.premiumUserDailyLimit` | 1000 | 付费用户每日使用限额 | 调整付费用户可用次数 |
| `limits.maxUploadSizeMB` | 5 | 文件上传最大尺寸（MB） | 限制上传文件大小 |
| `limits.maxFileCount` | 10 | 最大文件数量 | 限制一次上传文件个数 |

**使用场景**：
- 免费用户滥用服务 → 降低`freeUserDailyLimit`
- 付费用户需要更多配额 → 提升`premiumUserDailyLimit`
- 服务器存储紧张 → 降低`maxUploadSizeMB`

---

### 2️⃣ 功能开关 (features)

控制系统功能的启用/禁用。

| 配置键 | 默认值 | 说明 | 修改影响 |
|--------|--------|------|----------|
| `features.enableSignup` | true | 是否开放用户注册 | 关闭后新用户无法注册 |
| `features.enableOAuth` | true | 是否启用Google OAuth登录 | 关闭后只能邮箱密码登录 |
| `features.enableStripe` | true | 是否启用Stripe支付 | 关闭后无法订阅付费计划 |
| `features.maintenanceMode` | false | 维护模式开关 | 启用后禁止所有操作 |

**使用场景**：
- 系统维护 → 开启`maintenanceMode`
- 暂停新用户注册 → 关闭`enableSignup`
- 支付系统故障 → 暂时关闭`enableStripe`

---

### 3️⃣ 站点配置 (site)

网站的基础信息配置。

| 配置键 | 默认值 | 说明 | 修改影响 |
|--------|--------|------|----------|
| `site.title` | "WizPulseAI" | 站点标题 | 浏览器标签页显示 |
| `site.description` | "AI-Powered Business Solutions" | 站点描述 | SEO元标签 |
| `site.theme` | "dark" | 默认主题（dark/light） | 新用户默认主题 |
| `site.defaultLanguage` | "ja" | 默认语言（ja/en/ar/zh-TW） | 新用户默认语言 |

**使用场景**：
- 品牌升级 → 修改`title`和`description`
- 用户反馈亮色主题更友好 → 改为`light`
- 主要用户群变化 → 修改`defaultLanguage`

---

### 4️⃣ 第三方服务配置 (services)

控制外部服务的启用/禁用。

| 配置键 | 默认值 | 说明 | 修改影响 |
|--------|--------|------|----------|
| `services.stripeEnabled` | true | Stripe支付服务是否启用 | 影响订阅功能 |
| `services.analyticsEnabled` | true | 分析服务是否启用 | 影响数据统计 |
| `services.emailProvider` | "supabase" | 邮件服务提供商（supabase/sendgrid） | 切换邮件发送方式 |

**使用场景**：
- Stripe账号问题 → 暂时关闭`stripeEnabled`
- 节省成本 → 关闭`analyticsEnabled`
- 切换邮件服务商 → 修改`emailProvider`

## 如何修改配置

### 方法1：通过Dashboard界面（推荐）

**步骤**：
1. 访问配置中心页面
2. 找到要修改的配置项
3. 点击「编辑」按钮
4. 修改配置值：
   - **数字配置**：直接输入新数值
   - **开关配置**：选择"启用"或"禁用"
   - **文本配置**：输入新文本
5. 点击「保存」按钮
6. 等待确认提示："配置已更新，将在5分钟内生效"

**示例**：修改免费用户限额

```
操作前：limits.freeUserDailyLimit = 10
↓
1. 点击「编辑」
2. 输入新值：20
3. 点击「保存」
↓
操作后：limits.freeUserDailyLimit = 20（5分钟后生效）
```

---

### 方法2：通过API（高级用户）

```bash
# 获取配置
curl https://dashboard.wizpulseai.com/api/config/limits.freeUserDailyLimit

# 更新配置（需要管理员Token）
curl -X PUT https://dashboard.wizpulseai.com/api/admin/config \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer YOUR_ADMIN_TOKEN" \
  -d '{
    "config_key": "limits.freeUserDailyLimit",
    "config_value": 20,
    "change_reason": "用户反馈限额太低"
  }'
```

## 常见使用场景

### 场景1：免费用户滥用服务

**问题**：免费用户每天调用API过于频繁，影响服务器性能。

**解决方案**：
```
1. 登录配置中心
2. 找到「limits.freeUserDailyLimit」
3. 将值从 10 改为 5
4. 保存后等待5分钟生效
```

**效果**：新的限额将在5分钟后应用到所有免费用户。

---

### 场景2：系统紧急维护

**问题**：需要立即进行系统维护，禁止所有用户操作。

**解决方案**：
```
1. 登录配置中心
2. 找到「features.maintenanceMode」
3. 将值从 false 改为 true
4. 保存
```

**效果**：所有用户将看到"系统维护中"提示，无法进行操作。

**维护完成后**：将`maintenanceMode`改回`false`即可。

---

### 场景3：暂停新用户注册

**问题**：服务器容量接近上限，需要暂停新用户注册。

**解决方案**：
```
1. 登录配置中心
2. 找到「features.enableSignup」
3. 将值从 true 改为 false
4. 保存
```

**效果**：注册页面将显示"暂不接受新用户注册"。

---

### 场景4：调整付费用户限额

**问题**：付费用户反馈每日1000次限额不够用。

**解决方案**：
```
1. 登录配置中心
2. 找到「limits.premiumUserDailyLimit」
3. 将值从 1000 改为 2000
4. 保存
```

**效果**：付费用户每日可用次数提升到2000次。

## 注意事项

### ⚠️ 重要提醒

1. **配置生效时间**
   - 修改后需要 **5分钟** 才能完全生效
   - 原因：系统使用5分钟缓存，避免频繁查询数据库
   - 如需立即生效，请联系技术团队

2. **权限要求**
   - 只有 **管理员（admin角色）** 可以修改配置
   - 普通用户无法访问配置中心

3. **配置历史**
   - 每次修改都会自动记录历史
   - 包括：修改时间、修改人、旧值、新值、修改原因
   - 可用于审计和回溯

4. **谨慎操作**
   - 修改前请理解配置的影响范围
   - 建议在非高峰期修改关键配置
   - 修改后监控系统运行状态

5. **紧急回滚**
   - 如果修改导致问题，立即改回原值
   - 或联系技术团队协助回滚

---

### ✅ 最佳实践

1. **小步快跑**
   - 一次只修改一个配置
   - 观察效果后再继续修改

2. **记录原因**
   - 修改时填写清晰的原因
   - 方便后续回溯和审计

3. **渐进调整**
   - 限额类配置建议逐步调整
   - 例如：从10 → 15 → 20，而不是10 → 100

4. **高峰避让**
   - 避免在业务高峰期修改关键配置
   - 推荐在凌晨或用户较少时段操作

5. **团队沟通**
   - 重大配置修改前通知团队
   - 避免多人同时修改造成混乱

## 故障排查

### 问题1：无法访问配置中心

**症状**：访问`/dashboard/admin/config`显示"无权限"

**原因**：当前账号不是管理员角色

**解决**：
1. 检查账号角色：联系技术团队确认
2. 使用正确的管理员账号登录

---

### 问题2：修改后配置未生效

**症状**：修改配置并保存，但系统仍使用旧值

**原因**：配置缓存还未刷新（5分钟TTL）

**解决**：
1. 等待5分钟后再测试
2. 如紧急需要立即生效，联系技术团队清除缓存

---

### 问题3：保存配置时报错

**症状**：点击保存按钮后显示"保存失败"

**可能原因**：
- 网络连接问题
- 数据库连接问题
- 权限验证失败

**解决**：
1. 刷新页面重试
2. 检查网络连接
3. 重新登录
4. 联系技术团队排查

---

### 问题4：不确定配置的影响

**症状**：不清楚修改某个配置会产生什么影响

**解决**：
1. 查看本文档的"配置项完整说明"
2. 联系产品经理或技术团队咨询
3. 在测试环境先验证（如果有）

## 附录：配置优先级说明

系统使用三层配置机制（从高到低）：

```
1️⃣ 运行时配置（数据库）← Dashboard修改的配置
↓
2️⃣ 环境变量（.env文件）← 部署时配置
↓
3️⃣ 默认配置（代码）← 开发者定义的兜底值
```

**优先级规则**：
- Dashboard修改的配置 > 环境变量 > 默认值
- 如果数据库配置不存在，自动使用环境变量
- 如果环境变量不存在，自动使用默认值

**示例**：
```
配置：limits.freeUserDailyLimit

情况1：Dashboard设置为20 → 最终值：20
情况2：Dashboard未设置，环境变量=15 → 最终值：15
情况3：都未设置 → 最终值：10（默认值）
```
