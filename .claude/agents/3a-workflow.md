# 3A 作战模式 — 三 Agent 对抗式品质保证

> 所有重要产出必须过 3A。简单任务（文件整理、keyword研究）可跳过。

## 模式定义

```
Agent A（执行者）→ 产出初稿
    ↓
Agent B（专业审查）→ 领域专业角度检查，打分+具体修改意见
    ↓
Agent C（品牌审查）→ 整体品质、品牌调性、事实准确性
    ↓
三方都 PASS → 输出成果
任一 FAIL → 打回 Agent A 修改 → 重新过 B/C
```

## 各场景的 3A 配置

### 文章/内容
| 角色 | 职责 |
|------|------|
| A（写手）| 写文章初稿 |
| B（SEO审查员）| 关键词密度、标题、meta、内链、搜索意图匹配 |
| C（品牌审查员）| 品牌调性、事实准确性、有没有吹牛、可发布标准 |

### 设计系统
| 角色 | 职责 |
|------|------|
| A（设计师）| 调研参考 → 提取 token → 输出 DESIGN.md |
| B（CSS技术审查）| CSS 变量有效性、WCAG 对比度、Tailwind 兼容、跨浏览器 |
| C（品牌审查）| 审美水准、品牌一致性、主题间协调、实用性 |

### 代码修改
| 角色 | 职责 |
|------|------|
| A（开发者）| 实现功能/修复 |
| B（技术审查）| 代码质量、安全性、性能、架构合规 |
| C（UX审查）| 用户体验、视觉一致性、可访问性 |

## 评判标准

Agent B/C 各自打分（PASS / NEEDS_REVISION / FAIL）：
- **PASS**: 直接通过
- **NEEDS_REVISION**: 列出具体修改点，Agent A 修改后重审
- **FAIL**: 根本方向错误，需要重做

两个审查员都 PASS 才算最终通过。

## 执行原则

1. B 和 C 独立审查，不互相影响
2. 审查意见必须具体（行号/变量名/数值），不接受"感觉不好"
3. 最多 2 轮修改，2 轮后仍不过 → 升级给 bobo 决策
4. 审查报告简洁（每项 1-2 句），不写论文
